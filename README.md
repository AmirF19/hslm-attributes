# HSLM attribute inventory — Version B (passage-conditioned, per person)

simulated:illustrative; NO PASSING CLAIM; Q-88; exposure-derived; not a model of understanding; agent output is machine_unreviewed.

This repository holds one job of the Hierarchical Synthetic Language Model project: McRae-style semantic-feature inventories for 1,181 content lemmas, produced separately for three readers (persons A, B, C), each prompt conditioned on up to eight short passages (p1–p8) drawn only from that person's own prior-layer documents, with names masked. One fresh agent per item; the agent reads one prompt file and writes one JSON result file. Nothing else happens here: collection, canonicalisation and scoring run on the owner's machine after the results are pulled.

## Layout

- `job/items_B/<person>/<id>.txt` — the complete prompt for one (word, person): system prompt, reader clause, task with passages, output format. 1,181 per person; `job/items_B/<person>/items.jsonl` is the per-person index.
- `job/results_B/<person>/<id>.json` — one result per item, written by the agent that handled it. 687 already exist (A 288, B 222, C 177); never overwrite or delete them.
- `job/schema.json` — the result schema; `job/item.schema.json` — the item schema; `job/prompt_system.txt`, `job/prompt_source.json`, `job/category_blocks.json` — the prompt sources; `job/items_B.json` — per-item counts (windows, masked spans); `job/status_B.json` — the validator's current counts and the ids still missing or invalid per person.
- `tools/validate_results.py` — dependency-free validator: `python tools/validate_results.py` prints counts per person and writes `job/status_B.json` with the ids still missing or invalid. Run it before and after every batch.
- `workflows/inventory_b.js` — the fan-out script for the Workflow tool (one agent per item; `args = {"person": "A", "ids": [...]}`).
- `PROMPT_CLOUD_SESSION.md` — the brief for the session that runs this job.

## Rules

- Prompt files contain masked passages derived from private corpora. They are read by the generating agents and by the validator only. Do not quote, paraphrase or summarise passage text anywhere: not in commits, issues, pull requests, chat or notes. Results contain features, types, evidence labels (`p1`–`p8`) and a `general` flag; nothing else.
- Every result is exactly one JSON object `{"features": [{"feature": "...", "type": "...", "evidence": ["p3"], "general": false}, ...]}`; no prose, no code fences, no passage text. A result that fails validation is deleted and re-generated by a fresh agent.
- Commits carry no generated-by or co-author lines of any kind. Commit messages name counts only (for example `Version B: person A, batch 2, 500 results`).
- Order of work: person A, then C, then B. Never re-run an item that already has a valid result.
